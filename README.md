# zuey.me

Personal profile, Page Builder Studio, REST API, MCP Server, and AI Agent Skill for **Duy Nguyen (/zuey/)**.

- **Deployed URL**: [https://zuey.me](https://zuey.me)
- **Target Domain**: `zuey.me` (attached to Cloudflare Pages; DNS managed on Cloudflare)

---

## Architecture & Responsibilities

The system runs on **Cloudflare Pages** (SSR via `@astrojs/cloudflare`) backed by **Cloudflare D1** (`zuey_me_db`) and **PostHog** analytics (client events, plus server payment, subscription and sign-in events delivered from the D1 `analytics_outbox` by the scheduler worker; see [docs/analytics-events.md](docs/analytics-events.md#server-event-outbox)).

- **Public Profile & Modals**: `src/components/ProfileView.tsx` renders the link-in-bio interface, fast social share sheet, and QR code modal.
- **Data & Storage**: `src/db/` defines the schema (`src/db/types.ts`), initial seed data (`src/db/data.ts`), and edge D1 store (`src/db/store.ts`).
- **Page Builder Studio**: `src/pages/studio/index.astro` and `src/components/studio/StudioApp.tsx` provide SSO login, link ordering, theme switching, and API key management.
- **API & Docs**: `src/pages/api/` exposes REST endpoints and OpenAPI 3.1 specification; `src/pages/docs/index.astro` serves interactive Scalar documentation.
- **Machine & Agent Surfaces**:
  - LLM Context: `src/pages/llms.txt.ts` and `src/pages/llms-full.txt.ts`
  - Markdown Routes: `src/pages/index.md.ts`, `src/pages/links.md.ts`, `src/pages/profile.md.ts`
  - Checkout guide for agent-assisted purchases (public, non-personalized): `src/pages/checkout.md.ts` (`/checkout.md`), text in `src/lib/agent-commerce/checkout-markdown.ts`
  - MCP Server (members, OAuth 2.1): `src/pages/mcp.ts` (`/mcp`); legacy API-key endpoint: `src/pages/api/mcp.ts`
  - NPM CLI: `packages/cli/bin/zuey.js`
  - Agent Skill: `skills/zuey-me/SKILL.md`

AnyMD has no server-side tag filter, so the sync pages the library and filters locally. Scheduled by `.github/workflows/reads-sync.yml`.

Referrals (`referral-bridge.ts`): an account bound to a referrer gets the referee discount and earns its referrer commission on every course it buys; unbound buyers follow the program's first-order rule, and a typed code binds them. ## Operating Workflow

Executable commands are defined in `package.json`.

```bash
bun run dev      # Local development server
bun test         # Run automated test suite
bun run build    # Typecheck and build production bundle
```

### Deployment & CI/CD

- Workflow: `.github/workflows/deploy.yml` runs test suite and production build on push to `main`.
- Automated deploy to Cloudflare Pages runs when repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are configured.
- **Production Pages deploys come only from CI.** Never run `wrangler pages deploy` by hand, from any branch or worktree: a local `dist` is built from whatever that checkout holds, and it silently replaces the build of the latest `main` commit, which reverts fixes that are already merged. To ship, merge the PR into `main`. To redeploy `main` without a new commit, run the workflow on `main`: `gh workflow run deploy.yml --ref main`. Each deployment records the commit it was built from, which Cloudflare shows in its deployment list.
- Scheduler worker (cron jobs for the Pages app, `workers/scheduler/`): the same workflow bundles it on every PR and deploys it right after the Pages deploy on `main`; never `wrangler deploy` it by hand. Its `CRON_SECRET` secret is set once with `wrangler secret put CRON_SECRET --config workers/scheduler/wrangler.toml`, must equal the Pages secret, and survives deploys. The CI token needs *Workers Scripts: Edit* on top of *Cloudflare Pages: Edit*. Jobs are listed in `workers/scheduler/src/jobs.ts`; a job may mark a `503` code such as `community_unconfigured` as "skipped" so an unconfigured feature never fails the cron run, and may judge its own 200 result (the sweep logs a compact summary and fails only on a systemic error, meaning Telegram is unreachable or rate limited or an internal error occurred, in a run that made no progress; a membership that stays stuck only logs a warning with the error count). The Telegram community sweep runs as a dry run (report only) until the worker var `COMMUNITY_SWEEP_MODE` in `workers/scheduler/wrangler.toml` is changed to `live` in a reviewed PR.
- The Pages project, the D1 database and the `zuey.me` DNS zone live in the same Cloudflare account. Export that account's `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` before any wrangler command so a cached OAuth login for another account is never used.
- Remote D1 schema migrations (apply every file in `migrations/` in numeric order): `wrangler d1 execute zuey_me_db --remote --file=./migrations/<file>.sql -y`. Record a Time Travel bookmark first (`wrangler d1 time-travel info zuey_me_db`); `wrangler d1 export` refuses databases with FTS5 tables.
